# Memory Layer

Two stores, each with its own file and lifecycle:

| Store | File | Holds |
| ----- | ---- | ----- |
| Handoff | `.specs/STATE.md` | Pause snapshot - overwritten each pause |
| ADRs | `docs/adr/AD-NNN-slug.md` | Project-level decisions - append-only, one file each |

`STATE.md` carries the Handoff and nothing else. Decisions live in `docs/adr/`.

---

## Handoff (`.specs/STATE.md`)

~500 tokens, overwritten each pause. Written only when the user pauses or a session ends on purpose. A compaction gives no warning, so the live state of a feature is never here: it is the feature's own files - `spec.md` and `tasks.md` (`**Approved**:` lines, completion marks, `## Handoff` with `**Settled mid-build:**`, `**Dispatched:**` and `**Walked:**`), `proofs.md`, `verification.md`, `screens.md` - and git. On resume, this snapshot is a starting hypothesis reconciled against them (see Resume below).

**Format:**

```markdown
## Handoff

- **Feature**: [feature name / .specs path]
- **Phase / Task**: [e.g., Phase 2 / T4 - implement repository layer]
- **Completed**: [comma-separated task IDs or "none"]
- **In-progress** (file:line): [e.g., `src/billing/subscription.service.ts:88` - mid-write]
- **Next step**: [one sentence - exactly what to do next]
- **Blockers**: [none | description]
- **Uncommitted files**: [list or "none"]
- **Branch**: [git branch name]
```

**File shape:**

```markdown
# STATE

## Handoff

[latest snapshot…]
```

If the file does not yet exist, create it with only the `## Handoff` header.

The feature index (`.specs/features/AGENTS.md`, generated by `index.py features`) lists every feature's status and summary from the files in its folder. It does not read the Handoff: a paused feature shows as `in progress` or `specified` according to its files.

## ADRs (`docs/adr/`)

Records **project-level** decisions only: conventions, patterns, constraints, or cross-cutting technology choices that future features must follow or supersede.

**Not project-level → stays in the feature's `design.md` Tech Decisions table.**
Heuristic: would a different feature need to know about this? If yes → project-level. If no → feature-local.

**Record sparingly - the log stays useful only by staying small.** Even a project-level decision earns an ADR only when all three hold:

1. **Hard to reverse** - changing course later carries real cost.
2. **Surprising without context** - a future reader will look at the result and wonder "why did they do it this way?"
3. **The product of a real trade-off** - there were genuine alternatives and you chose one for specific reasons.

If any one is missing, skip it: an easily-reversed choice you will just reverse; an unsurprising one nobody questions; a no-alternative choice records nothing beyond "we did the obvious thing." What typically qualifies: architectural shape, integration patterns between areas, technology choices that carry lock-in, boundary and ownership decisions, and deliberate deviations from the obvious path. A choice that clears all three but is only feature-local still stays in `design.md`.

An answer the user gives to a departure from a binding source is also an ADR: it holds the question and the answer, and the spec's `## Differences from the source` row cites it as `y - AD-NNN`. `validate_spec.py` reads the active ones from `docs/adr/`.

### File format

One file per decision: `docs/adr/AD-NNN-slug.md` at the project root, created lazily (the folder appears with the first ADR).

```markdown
# AD-NNN: [short title]

- **Decision**: [what was decided - one sentence]
- **Reason**: [why this option was chosen]
- **Trade-off**: [what was given up]
- **Scope**: [which features / packages / layers this governs]
- **Date**: YYYY-MM-DD
- **Status**: active | superseded by AD-NNN
```

**Supersession:** when a new decision replaces an old one, write a new ADR and change the old file's `Status` to `superseded by AD-NNN`. Never delete an ADR - the history is the audit trail.

**Numbering:** the highest existing `AD-NNN` in `docs/adr/` + 1; `AD-001` when the folder is empty or absent. Numbers are project-scoped and never reused.

### Index (generated)

After every ADR write or supersession, regenerate the index:

```
python3 <skill-dir>/scripts/index.py adr
```

This writes `docs/adr/AGENTS.md` - a table of the `active` ADRs (ID, Scope, Decision) plus a short list of superseded ones - and, once, a `docs/adr/CLAUDE.md` containing `@AGENTS.md`. Never edit the index by hand. An ADR without a `Decision` or with an invalid `Status` makes the script exit 1 and name the file; fix the ADR, do not work around the script.

Readers (Design, Resume) read `docs/adr/AGENTS.md` first and open a full ADR only when its `Scope` touches the work.

A `## Decisions` section left in an old `STATE.md` still counts for `validate_spec.py`, but nothing else reads it. Transcribe those entries into `docs/adr/` when they should govern new work.

## Read / Write triggers

| Trigger | Store | Operation |
| ------- | ----- | --------- |
| Design phase, Step 1 (Load Context) | ADRs | **Read** `docs/adr/AGENTS.md` - conform to active ADRs or supersede |
| Design phase, Tech Decisions step | ADRs | **Write** a new ADR - only for project-level decisions - then `index.py adr` |
| A binding source is departed from | ADRs | **Write** the question and the answer as an ADR, then `index.py adr` |
| Pause work / end of session | Handoff | **Replace** the body of `## Handoff` |
| Resume work / start of session | Handoff, ADRs | **Read** the snapshot and `docs/adr/AGENTS.md`, then reconcile with git before acting |
| After a compaction | both, then the feature's files | **Read** - the same Resume procedure |

---

## Pause / Resume Procedure

### Pause

1. Replace the body of `## Handoff` in `.specs/STATE.md` (everything between `## Handoff` and EOF) with the current snapshot.
2. Commit or stash outstanding changes as appropriate.

### Resume - a new session, or after a compaction

A compaction is a resume: the summary keeps the task and drops the rules.

1. Re-read `SKILL.md`, then the reference for the phase the files show (table below).
2. Run `python3 <skill-dir>/scripts/index.py features --check` (regenerate with `index.py features` if stale), then read `.specs/features/AGENTS.md`, `.specs/STATE.md` (`## Handoff`) and `docs/adr/AGENTS.md`. Re-confirm the active ADRs: nothing superseded since?
3. Read the feature's files. The `STATE.md` `## Handoff`, when present, is a **hypothesis**, not ground truth.
4. **Reconcile with git before editing anything:**
   - Current branch vs Handoff `Branch`
   - `git status --porcelain` (uncommitted / unexpected paths)
   - Recent commits on the branch (messages and touched files)
   - `tasks.md` completion marks and, when present, gate evidence / commit references
5. **Resolve conflicts with evidence, not narrative:**
   - A task with a green gate and an atomic commit already on the branch → do **not** redo it; mark it complete in `tasks.md` if the file still shows it open, then continue from the next incomplete task
   - Partial unverified work in the working tree → preserve it, re-run the relevant gate, then finish the status+commit cycle
   - Stale or missing Handoff → rebuild next-step from git + the feature's files
   - Unexplained local changes you cannot map to the current task → STOP and ask; do not discard them
6. After a compaction in the middle of a run, continue when the files and git agree, and stop only on a conflict. In a new session, propose the reconciled next step to the user before writing any code.

**Where the files put you** - the first row that holds:

| The files show | Next |
| --- | --- |
| `spec.md` with no `**Approved**:` line | Specify: open questions still the user's - present the spec with them and stop |
| no `tasks.md`, and the scope owes one | Design or Tasks |
| `tasks.md` with no `**Approved**:` line | present the tasks and stop |
| an open task | Execute it; one whose commit is on the branch is done - mark it |
| every task done, no `**Walked:**` line (a feature with a screen) | the walk and the pictures (implement.md step 9) |
| no `proofs.md`, or one at another commit than `HEAD` before any dispatch | `check_proofs.py` (step 10.1) |
| `**Dispatched:**` names a sub-agent whose file is not on disk (`verification.md`, `screens.md`, a batch's commits) | wait for it; send it again only when it cannot return - a new session - and say so on the line |
| `verification.md` with an open finding, or `screens.md` `**Round**: 1` that diverges | the fix pass, then round 2 |
| `screens.md` `**Round**: 2` | the script and the gate; what still fails goes to the user - there is no third round |
